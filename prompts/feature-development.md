# 功能开发 Prompt

- 适用场景：新增功能或跨模块调整。
- 需要填写的输入：功能目标、影响范围、验收标准和已知限制。
- 可复制提示词：

```text
先执行项目接入检查并读取相关规则。功能需求严格分两阶段：先只做分析，查明现状、目标、范围、验收标准、假设和风险，给出推荐方案；此阶段不改实现、不生成补丁、不开始实施。把分析结果交给我确认，只有我确认后才实施；我在分析后说“按推荐方案继续”即视为确认，不重复问同一授权。初始需求或笼统实施授权不等于确认尚未展示的分析结论。把需求拆成可验证的行为，列出受影响的入口、调用链、数据和风险。改造已有行为时先查明当前行为及依据，再标记保留、新增、修改和删除项；Medium/Large、涉及接口/数据/权限或我要求深入分析时，Large 使用 `templates/large-task-record.md`，把需求、分析、方案、任务、验证和审查写在同一份 Markdown 记录中，不按模板拆成多个文件；Medium 只在同一份需求记录中补充适用分析项，并让验收编号贯穿方案、任务和验证。只有存在会改变实现、风险或验收的关键未知项，或我明确要求深入把关时，才额外按 `core/task-routing.md` 启动内置需求压力测试：先查证可从项目和工具获得的事实，再一次问一个关键问题并给出推荐默认方案；小而明确的任务可以跳过额外压力测试，但仍须完成简明需求分析并等待我确认。给出范围、方案和验证矩阵；分析未获确认前暂停实施，确认后不重复索要同一实施授权。修改保持最小范围，完成后报告文件、测试和未覆盖风险。
```

- 预期输出：先给范围、现状与变化、推荐方案、风险和验收标准并等待确认；确认后再实施，并报告文件、验证证据和未覆盖风险。
- 对应 Skill：`targeted-verification`
- 对应 Playbook：`full-development-lifecycle.md`
