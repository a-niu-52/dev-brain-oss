# 项目模式参考

## 多技术栈并行

- 证据类型：近期活跃项目的目录、构建清单和规则文件。
- 适用范围：需要在 Vue/TypeScript、Flutter、Java 和多端桥接之间切换的任务。
- 不能推导出的结论：不能根据技术栈名称猜测具体命令、分支或目录。

## 工作区经常存在用户修改

- 证据类型：多个项目的 Git 状态检查。
- 适用范围：开始修改、更新或远程操作前。
- 不能推导出的结论：不能因为工作区脏就擅自 stash、reset 或迁移。

## 中大型功能使用设计和计划文档

- 证据类型：项目中的 specs、plans、OpenSpec 和设计文档。
- 适用范围：跨模块、跨平台或风险较高的任务。
- 不能推导出的结论：简单文档修正不需要强行创建长计划。

## 文档有同步维护触发器

- 证据类型：项目知识文档和规则文件中的维护约定。
- 适用范围：目录、入口、调用链、接口和质量门禁变化。
- 不能推导出的结论：文档不能替代真实代码和构建配置。

## 分支策略不统一

- 证据类型：近期仓库分支和提交历史。
- 适用范围：Git 交付、合并和推送前检查。
- 不能推导出的结论：不能把 `main`、`dev` 或个人分支写成所有项目的固定默认值。
