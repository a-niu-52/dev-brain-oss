# 个人 AI 工作大脑方案备忘

> 状态：讨论稿，供后续读取、分析和与实施方案对比。尚未作为正式设计定稿。

## 目标

让工作台能够把自然语言请求整理成可执行的需求，按需读取项目知识、技能和工具，并按一致的开发流程交付结果。

## 参考项目的职责

| 项目 | 可借鉴的职责 |
| --- | --- |
| `ai-workbench-main` | 项目知识、规则、技能和流程的索引方式 |
| OpenSpec | 将需求整理成提案、规格、设计和任务，再实施与归档 |
| Superpowers | 需求讨论、调试、测试和代码审查等开发方法 |
| Dev Brain | 保存个人习惯，并通过不同工具的适配层供跨项目读取 |

## 1. 从对话提炼需求

先识别任务类型：提问、Bug、功能需求、代码审查或 Git 操作。再提取目标结果、当前表现、已知事实、推测、待确认项、范围、完成标准和验证方式。

建议使用统一需求卡：

```text
任务类型：
目标项目：
期望结果：
当前表现：
已知事实：
假设与待确认：
本次范围：
完成标准：
验证方式：
```

如果不同理解会导致不同实现，先澄清关键点；意图和范围明确时，直接进入对应流程。

## 2. 按需选择技能和工具

技能说明遇到某类任务时如何工作；工具负责实际操作。建议按以下顺序选择：

1. 读取工作台规则和路由索引。
2. 根据任务类型、项目技术栈和风险选取少量相关技能。
3. 读取匹配技能的详细说明及相关项目资料。
4. 检查当前环境可用工具，再选择工具执行。
5. 按技能要求验证并汇报证据。

每项技能或工具的索引信息建议包括：触发条件、所需输入、产出、依赖、支持环境、风险等级和验证方式。未安装或不可用时，说明限制并采用可行替代方案。

| 任务 | 建议读取 | 典型操作 |
| --- | --- | --- |
| 接手新项目 | 项目接手技能、项目规则和项目卡 | 检查 Git 状态、入口文件和测试命令 |
| 修复 Bug | 调试技能、项目卡 | 复现问题、定位原因、运行相关测试 |
| 新增功能 | 需求澄清和开发流程技能 | 明确规格、拆解任务、实现和验证 |
| 准备推送 | Git 交付规则 | 汇报分支、待推送提交和远程目标 |

## 3. 完整开发流程

```text
读取项目规则与 Git 状态
  → 整理需求卡
  → 选择 Bug、功能或其他任务流程
  → 明确方案和完成标准
  → 拆分实施任务
  → 按需准备分支或隔离环境
  → 实现并做针对性验证
  → 审查并汇报结果
  → 按授权提交或推送
  → 提炼可复用知识
```

每个阶段都应有可检查的产物，例如需求卡、设计与验收标准、任务清单、测试证据、审查结论和交付状态。Git 提交说明使用中文；推送前说明分支、提交数量和远程目标，并遵循用户确认规则。

## 对当前 Dev Brain 的建议

1. 增加需求模板和澄清规则，把口语请求转为有范围和完成标准的需求卡。
2. 建立技能与工具路由表，按任务、项目技术栈和风险指向相关资料与能力。
3. 补齐端到端开发流程，写清阶段产物、检查点和交付规则。
4. 增加当前项目映射，帮助新任务找到本机项目卡和项目规则。
5. 增加路由验证用例，覆盖修 Bug、加功能、代码审查和 Git 交付等任务。

建议保留 `ai-workbench-main` 的知识索引思路，用 OpenSpec 管理变更产物，并借鉴 Superpowers 的开发方法；由 Dev Brain 负责把这些能力连到个人项目知识和不同工具的入口上。
