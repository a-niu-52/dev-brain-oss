# 交付功能

开始前读取 `core/task-routing.md` 和本 Playbook。多阶段功能使用 `playbooks/full-development-lifecycle.md`，不在简单任务中自动创建计划文件。

## 输入

需求、验收标准、改动范围、项目规则和已运行验证。

## 步骤

1. 完成需求卡、验收标准和适用的项目接手检查；只澄清会改变实现或验收的未知项。
2. 中大型需求先按需写方案和任务清单，再按项目约定先写测试或复现。
3. 聚焦实现，保留用户已有修改，同步受影响的测试与项目文档。
4. 使用 `targeted-verification` 运行真实项目验证，并逐项核对验收标准。
5. 使用 `code-review` 检查差异、安全、兼容性与遗漏。
6. 使用 `git-delivery` 检查分支、工作区、差异和提交概要。
7. 未经用户明确确认，不执行 `git push`。

## 验证

- 需求验收项逐项有证据。
- 工作区和敏感信息检查通过。
- 本地提交信息具体、简短且符合项目规则。

## 停止条件

- 验证失败或证据不足。
- 发现敏感信息、未解释的大范围差异或远程冲突。
- 用户没有明确确认推送。
