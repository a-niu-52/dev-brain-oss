# 开始新项目

## 输入

项目目录、仓库地址、预期目标、已有规则文件和可用构建工具。

## 步骤

1. 运行 `project-onboarding`，记录工作区、分支、远程和项目入口。
2. 读取真实构建清单、项目规则、架构文档和匹配的项目知识卡片。
3. 选择技术栈 Profile，列出项目规则覆盖的例外。
4. 建立本次任务的目标、影响范围、风险和验证矩阵。
5. 用户确认范围后再开始修改。

## 验证

- 能说明当前生效的规则来源。
- 能给出真实安装、检查、测试和构建命令。
- 能列出目标分支和未推送提交状态。

## 停止条件

- 工作区已有修改且任务范围不清。
- 找不到真实构建入口。
- 项目规则与请求冲突且用户尚未决定。
