# 完整开发闭环

```text
准备 → 理解 → 接手 → 方案 → 实施 → 验证 → 审查 → 交付 → 沉淀
```

## 阶段与检查点

1. **准备**：区分咨询、分析、Review、修改与交付；确认当前用户要求和授权范围。
2. **理解**：Medium 或用户要求保存的需求使用一份 `templates/requirement-card.md`；Large 使用 `templates/large-task-record.md`，不再另建需求卡。小任务在对话内明确验收即可。只澄清会改变实现、风险或验收的未知项。符合 `core/task-routing.md` 触发条件时，按需启动内置需求压力测试：代理先查事实，再逐个确认关键决策并给出推荐默认方案；小而明确的任务默认跳过，但用户明确要求深入把关时，小而明确的任务也进入压力测试；不穷尽无关分支。
3. **接手**：按需调用 `project-onboarding`，读取项目规则、Git 工作区、真实入口和命令；选择匹配 Profile 与项目卡，不覆盖已有改动。
4. **方案**：Small 直接处理；Medium 在需求卡或对话中写明影响范围和任务清单；Large 在同一份 `templates/large-task-record.md` 中补齐设计和任务章节。`templates/change-design.md`、`templates/task-plan.md` 是章节参考，不作为额外输出文件。项目格式影响内容组织；若其硬性要求拆分文件，先说明冲突。
5. **实施**：功能需求只有在用户确认范围、验收标准和推荐方案后才开始实现；故障按 `debugging` 与 `playbooks/fix-bug.md` 先完成复现和根因分析，再按修复任务的授权范围处理。实施时先有复现/测试，再做聚焦修改；一次只推进一个任务，不扩大到无关重构。
6. **验证**：使用 `targeted-verification` 和实际项目命令；逐项核对完成标准。分析确认前不运行实施验证；确认实施后，Medium/Large 的真实命令与结果记入原需求记录；`templates/verification-report.md` 仅作为章节参考，不另生成验证文件。
7. **审查**：使用 `code-review` / `playbooks/review-change.md` 检查差异、安全、兼容性和文档同步；Large 的审查发现与处理结果记入同一需求记录，不另建审查文件；审查发现未处理前不能称完成。
8. **交付**：使用 `git-delivery`；Large 的变更、测试、分支和工作区状态记入同一需求记录，再汇报交付情况。未经用户明确确认，不执行 `git push`。
9. **沉淀**：只有重复、稳定、有证据且可脱敏的经验才交给 `extract-project-knowledge`，先入候选区。

### 需求分析检查点

进入方案前，对行为改造核实现有入口、当前行为和依据，并记录保留/新增/修改/删除范围。Large 按 `core/task-routing.md` 使用 `templates/large-task-record.md`，只生成这一份过程记录；只填写适用分析项。Medium/Large 或高风险需求为验收项编号，并在同一份记录中沿用。分析阶段只查证和整理，不修改实现；向用户展示范围、验收、风险与推荐方案并得到确认后，才进入实施。用户明确回复“按推荐方案继续”即可视为确认。项目自己的需求规范优先，但不得默认拆成多份过程文件。

## 任务规模

| 规模 | 判断 | 产物 |
| --- | --- | --- |
| Small | 咨询、只读，或单点且低风险改动，不触及共享契约、数据、权限或外部系统 | 简化理解、定向验证；不自动创建文件 |
| Medium | 一个业务流程/子系统内多文件，验收基本明确 | 先分析并确认需求卡；确认后实施和审查 |
| Large | 跨模块/平台、公共接口、迁移、安全/权限、资金、生产或外部写入；关键需求未知也升级 | 先在一份单文件记录中完成分析并等待确认；确认后按同一文件实施、验证和审查 |

风险可以提高流程等级；仅仅文件较多不会自动升级。未影响方案的次要细节允许明确假设继续。

## 文件与暂停规则

- 只有用户要求保存、项目规则要求留档或任务跨会话时才创建持久化产物；Large 过程信息合并到一个 Markdown 文件，创建前说明目标仓库内的准确路径。
- 暂停且确需恢复时记录阶段、分支、未提交修改、验证结果和下一步；Large 将这些内容追加到原单文件记录，不另建交接文件。其他任务可使用 `templates/session-handoff.md`。不得把未提交修改误报为已保存。
- 分析尚未确认时停在分析阶段，不开始实现；阶段阻塞时说明证据、风险和所需决定，不跳过检查点或伪造验证结果。
