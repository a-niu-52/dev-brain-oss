# Targeted Verification

1. 读取项目真实 scripts、构建清单和测试入口。
2. 将改动分为内容、类型、逻辑、数据、权限、设备和跨端协议风险。
3. 为每类风险选择最小可复现命令，并说明命令覆盖范围。
4. 区分静态检查、单测、集成测试、端到端测试和构建。
5. 报告未运行的验证、环境限制和剩余风险。
6. 不把构建通过等同于测试通过。
7. 移动端 App 或涉及移动端的项目不启动真机、模拟器、仿真器或设备形态模拟；选择不启动 App/设备的检查和测试。无法由这些检查覆盖的设备运行时行为标为未验证。
