# 测试规则

## 规则

- 先根据改动范围和风险选择最小但充分的验证矩阵。
- 修复缺陷必须覆盖原问题或增加可重复的回归检查。
- 构建通过不等同于测试通过，静态检查通过不等同于运行时流程通过。
- 完成前提供新鲜命令输出，并区分已验证、未验证和环境限制。
- 移动端 App 及涉及移动端验证的项目不使用真机、模拟器、仿真器或设备形态模拟。只运行不启动 App/设备的静态检查、单元/组件/契约测试和构建检查；若现有测试会启动设备环境，则跳过并记录为未验证。
- 依赖设备运行时、硬件或系统权限的行为无法通过上述检查确认时，明确记录未验证项和剩余风险；不把静态检查、Mock/替身测试或构建结果表述为设备运行时已通过。

## 原因

验证结果只有和改动风险对应，才能支持可靠交付。

## 例外

纯文档变更可以执行内容契约和链接检查，仍需说明未运行业务测试。
